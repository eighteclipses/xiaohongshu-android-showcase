# 内容审核与批量管理使用说明

## 已实现的流程

- 管理员维护平台关键词。标题、正文、话题经过全半角、大小写和零宽字符规范化后进行普通文本匹配，不使用正则。
- 新公开笔记无命中则通过；命中后显示“待审核”，DeepSeek 只给复审建议，人工决定通过或驳回。
- 修改公开内容会重新检查；曾被驳回或隐藏的笔记再次提交，必须经过人工审核。
- 已公开笔记被举报后继续展示。同版本举报合并到一个案件，人工决定保留或隐藏。
- 内容变化会使原案件失效。后台可明确选择“按当前版本重新审核”，旧内容、举报和审核历史继续保留。
- 删除笔记会进入回收站，恢复后为私密草稿，需要重新提交才能公开。图片及互动记录保留。

## 网页操作

管理后台：[http://localhost:3001/admin](http://localhost:3001/admin)。

1. **关键词词库**：新增、编辑、批量启用/停用/删除，或上传 UTF-8 CSV。模板中的示例词默认停用。
2. **人工审核 / AI 待办**：筛选案件，查看原文、命中片段、AI 建议及审核时间线；提交人工结论必须填写理由。
3. **举报再审**：查看举报关联案件；“保留笔记”驳回举报，“隐藏笔记”停止公开展示。
4. **笔记管理 / 回收站**：全选当前页后批量通过、驳回、隐藏、重新扫描、请求 AI、删除或恢复。
5. 用户、评论、媒体和日志采用服务端筛选分页。每页支持 10、20、50 条，可直接跳页。

创作者平台：[http://localhost:3001/](http://localhost:3001/)。

- 内容管理支持公开、私密、审核中、未通过、草稿、回收站筛选，展示审核说明和版本。
- CSV 导入全部保存为本人私密草稿。支持批量提交审核、修改可见范围、转草稿、移入回收站和恢复。
- 批量执行前展示所选清单，执行后展示每条失败原因；切换筛选或分页会清空选择。
- 审核通知区域显示近期人工处理结果。网络错误不会把用户误退出登录。

单次批量操作或 CSV 导入最多 100 条；CSV 不超过 1MB。修正失败行后可再次导入，新文件使用新的请求编号；同一请求重试不会重复新增。

## Android

- 本地 Room 已从版本 9 增量升级到 10，保留已有数据。
- 发布等待服务端确认，区分“已发布”“待审核”“待同步”。网络恢复后会重试本人的待同步笔记。
- 个人笔记展示待审、驳回等状态；点击未通过的笔记可以打开编辑器查看理由并修改。
- 审核结果同步到消息页。公开信息流、搜索、收藏等使用已确认的审核状态，不再用未审核的随机笔记补足列表。
- 旧版本响应不会覆盖较新的本地审核结果；内容冲突会提示加载服务器最新版本。
- 删除入口使用服务端回收站。未同步的本地内容需联网同步后再移入回收站，失败不会丢弃本机内容。

## 接口与运行

新增接口主要包括：

| 接口 | 用途 |
|---|---|
| `GET/POST /api/admin/keyword-rules` | 分页查询、创建词库规则 |
| `PATCH/DELETE /api/admin/keyword-rules/:id` | 修改、删除规则 |
| `POST /api/admin/keyword-rules/import`、`/batch` | CSV 导入、批量启停及删除 |
| `GET /api/admin/moderation-cases`、`/:id` | 查询案件与详情 |
| `POST /api/admin/moderation-cases/:id/decision` | 人工裁定 |
| `POST /api/admin/moderation-cases/:id/retry-ai`、`/rebase` | AI 重试、确认复查新版本 |
| `POST /api/admin/posts/batch` | 管理员批量处理笔记 |
| `POST /api/creators/me/posts/batch`、`/import` | 本人笔记批量处理、CSV 草稿导入 |
| `GET /api/posts/sync?ids=...` | Android 更新已有笔记的审核状态 |

列表返回 `data.items` 和 `data.pagination`，并保留 `posts/users/reports` 等对应的记录别名。更新、删除、审核请求需携带 `content_version`，过期返回 409。普通发布请求传入 `status` 不会改变审核结论。

批量请求示例：

```json
{"action":"delete","items":[{"id":"笔记编号","content_version":1}]}
```

CSV 导入请求使用 `{ "request_id": "一次导入的稳定编号", "csv": "CSV 文本" }`。关键词表头为 `term,category,enabled`；草稿表头为 `title,content,topics,location`，话题使用 `|` 分隔。

执行 `npm --prefix server run migrate:moderation` 可显式补齐增量结构，后台启动也会检查结构。迁移只新增字段和表，不清空原有记录。原有管理员列表脚本需从新的分页结构读取数据，并在修改操作中传入版本。

AI 审核复用服务端 `.env` 的 DeepSeek 配置，不向客户端下发密钥。队列单进程最多并发两项，每五秒检查待办；失败在一分钟、五分钟后重试。失败后仍可人工处理，AI 不会自动放行。重启会恢复未完成任务，人工已处理或版本过期的结果仅保留历史。

本版保留单实例 Node.js 和内存业务数据配合 MySQL/JSON 持久化的架构，未改为多实例分布式系统；审核对象仅为文字，不包含图片 OCR 或视频内容识别。

配置为 MySQL 时，数据库不可用将停止启动，不会自动切换到缺少审核词库的 JSON 数据。需要独立 JSON 演示时请明确设置 `STORAGE=json`。
