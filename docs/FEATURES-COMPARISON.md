## 八、工程质量对比

| 维度 | 本项目现状 |
|---|---|
| 联调环境 | `backend_base_url` 已改为 `10.0.2.2:3001/api`（模拟器直连宿主机后端；真机需改回局域网 IP） |
| 后端 | Express（JSON/MySQL 双模），20 篇种子笔记、15 个种子用户（user1..15/123456）、管理后台、审核流、创作者平台 |
| 数据一致性 | 本地 Room 优先 + 服务端异步同步，失败入 PendingSyncStore 重试队列 |
| 已修复的脆弱实现 | ShopDataRepository 的 `Thread.sleep(1000)`+轮询改为 awaitReady 栅栏 + 单次查询 |
| 已知限制 | `Room.allowMainThreadQueries()` 保留；评论回复关系与评论点赞仅本机（服务端无字段）；群聊/直播/滤镜未实现；同城乡无真实地理过滤 |
| 测试 | 模拟器 GUI 走查（截图见 `docs/test-screenshots/`），无自动化测试 |

## 九、结论

- 本项目在**核心社交闭环**（信息流 → 详情 → 点赞/收藏/评论/关注 → 发布 → 搜索 → 消息通知）上已对齐真实小红书的主干体验，交互细节（双击点赞、嵌套回复、评论键盘适配、@提及）本次迭代后与真实应用基本一致。
- 与 GitHub 同类项目相比：RedBookComposeDemo 只覆盖瀑布流+详情转场；RN-XiaoHongShu 只覆盖四个页面；XJingWei 功能面最广但为 uni-app 跨端实现。本项目是少数**原生 Java + 自带可用后端（含审核/管理台）**的完整仿写。
- 剩余差距主要在：内容推荐（相关推荐/个性化）、媒体编辑（滤镜贴纸）、LBS 同城、直播电商等扩展能力，以及服务端评论树/评论点赞字段补齐。
