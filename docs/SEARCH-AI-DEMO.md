# 搜索修复与 DeepSeek 笔记助手

更新日期：2026-09-11。

## 本次修复

- 搜索结果页的 `usersRecyclerView` 未绑定就调用 `setLayoutManager`，触发空指针闪退。已补全绑定。
- 分类统一为“笔记 / 用户 / 商品”，对应列表独立显示；排序栏只用于笔记。
- 搜索支持键盘搜索动作、加载提示、按分类显示空结果、失败点击重试；页面关闭后不再刷新失效界面。
- 搜索返回的视频笔记进入视频详情，避免全部当图文打开。
- AI 批量话题一次性更新并展示在编辑器，避免 LiveData 连续异步更新丢失前面的标签。

## AI 功能怎么演示

1. 登录 Android 账号，点击底部“发布”→“写文字”。
2. 写一句想法，例如“整理一份大学生图书馆自习计划，不编造个人经历”，点“下一步”。
3. 点击“AI 笔记助手 · 标题 / 正文 / 话题”。
4. 确认要发送的想法，选择生活记录、实用攻略或体验分享，点击生成。
5. 查看 DeepSeek 生成的标题、正文与话题，核实后点击“填入编辑器”。
6. 继续编辑、添加图片、设置公开或私密，最后由本人决定保存草稿或发布。

生成与发布是两个独立动作。生成请求不会创建笔记，不读取或上传其他用户的内容。填入会替换当前标题和正文，保留图片、地点与可见范围，并合并话题。

## 实现结构

```text
Android AiNoteAssistant
  → 带登录令牌的 POST /api/ai/note-assistant
  → Express 身份检查、输入检查、并发与频率限制
  → DeepSeek Chat Completions（JSON 输出）
  → 解析并校验 title / content / topics
  → Android 预览 → 用户确认 → 填入笔记编辑器
```

当前模型为 `deepseek-flash`，关闭思考模式，限制输出长度。调用使用 [DeepSeek 官方 Chat Completions 接口](https://api-docs.deepseek.com/api/create-chat-completion/)。密钥只在 `server/.env` 的 `DEEPSEEK_API_KEY` 中，模型配置为 `DEEPSEEK_MODEL`；Android 只知道本项目的后台地址。

服务端设置 45 秒生成超时，每个账号同时只允许一次生成，每分钟最多六次。额度不足、认证失败、超时和格式错误均有明确提示，不会用模板内容冒充成功的 AI 调用。

## 与真实小红书的对比

| 方向 | 真实产品的公开资料 | 本项目实际实现与边界 |
|---|---|---|
| 搜索分类 | 官方跳转文档包含笔记、商品、用户搜索结果类型 | 已恢复三类搜索与切换；商品为本项目演示数据 |
| 搜索入口 | 官方文档列出历史词、推荐词、自动补全等入口 | 有本地历史、推荐/联想词及键盘搜索；热点来自项目数据，不是小红书实时热榜 |
| 排序 | 本次未登录核验真实 App 当前版本的全部筛选项 | 支持对已加载笔记结果进行综合、最新、最热排序；远程搜索目前最多取首批 20 条，不宣称是全站排序或完整分页 |
| AI | 公开报道介绍小红书“点点”围绕平台内容提供生活搜索帮助 | 本项目选择“笔记创作助手”，真实调用 DeepSeek；不接入小红书笔记库，不是点点或检索增强问答的复刻 |
| 创作者数据 | 蒲公英官方介绍创作者与笔记数据分析能力 | 提供本人公开笔记数、互动统计、近七天趋势；没有商业投放归因和真实交易分析 |

## 答辩可以这样解释

“搜索故障是一个控件初始化遗漏造成的空指针。我把控件绑定、分类索引和列表切换一起修正，并增加了 Android 回归测试。AI 部分接入现成的 DeepSeek 大模型，重点工作是后端封装、身份验证、结构化输出、异常处理，以及让生成结果真正进入笔记编辑流程。模型由 DeepSeek 提供，并非自行训练。”

AI 内容仍可能不准确或添加素材未提供的表述，需要本人核对；本功能不提供实时搜索、真实定位、个性化推荐模型或自动发布。
